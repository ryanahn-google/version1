app/__init__.py Lazy Loading

app/agent.py ADK Root Agent

최상위 오케스트레이터 에이전트 mvc_orchestrator를 정의합니다. 모델은 gemini-3.1-pro-preview (location="global")를 바인딩하고, ADK FunctionTool 5종(parse_campaign_prompt, create_campaign_session, get_campaign_status, approve_campaign_stage, rollback_campaign_stage)을 장착합니다. 단위 테스트 격리를 위해 _IntegrationTestMockLlm 헬퍼를 내장하여 외부 자격증명 없이도 100% 모의 테스트를 지원합니다.

app/fast_api_app.py FastAPI Factory

애플리케이션 수명주기(lifespan) 컨텍스트를 관리합니다. 기동 시 DB 풀 초기화, ADK Runner 인스턴스를 생성하여 app.state.runner에 바인딩, A2A JSON-RPC 엔드포인트를 마운트합니다. 프로덕션 보안 강화를 위해 FastAPI.__init__을 인터셉트하여 대외 공격 표면인 /docs 및 /redoc을 비활성화하며, React 19 SPA 정적 에셋을 /static 및 /mvc에 단일 오리진으로 마운트합니다.

app/settings.py Pydantic BaseSettings

OS 환경변수의 직접 호출(os.getenv)을 100% 금지하고, 도메인별로 세분화된 Pydantic 설정 클래스(ApplicationSettings, SecuritySettings, A2AClientSettings, DatabaseSettings, GoogleCloudSettings, TelemetrySettings)로 캡슐화합니다. get_settings() 싱글톤 함수에 @lru_cache를 적용하여 무비용 고속 프로퍼티 조회를 보장합니다.

app/storage_service.py GCS & V4 Signed URL Service

Google Cloud Storage 오브젝트 저장 및 Domain-Restricted Sharing (DRS) 정책 준수를 전담합니다. 모든 마케팅 에셋은 테넌트 격리 경로(users/{user_id}/campaigns/{session_id}/{filename})로 엄격히 관리되며, uuid.UUID 파싱을 통해 테넌트 누수를 방지합니다. generate_v4_signed_url()은 서비스 계정 키 파일 없이 IAM Credentials API(signBlob)를 호출하여 60분 만료의 V4 서명 URL을 발급하고, save_visual_marketing_asset()은 GCS SDK 실패 시 ADC 토큰 기반의 직접 HTTP REST API 업로드로 이중화되어 있습니다.

2.2. 데이터 모델 및 Pydantic v2 계약 계층 (`models/`, `schemas/`)

app/models/campaign.py Table: orchestrator_sessions

SQLAlchemy ORM 엔티티 CampaignSessionModel을 정의합니다. 물리 테이블명은 **orchestrator_sessions**이며, 기본키 session_id(UUID v4), 외래키 user_id(users.user_id, ON DELETE SET NULL), 진행 상태(current_stage, status 인덱스), 4개 서브에이전트 산출물을 통합 저장하는 deliverables(JSON/JSONB), 피드백 누적 필드 feedback_history를 보유합니다.

app/models/user.py & base.py Tables: users, user_sessions

UserModel(users)은 마케터의 구글 OIDC 고유 식별자(google_sub), 이메일, 이름, 프로필 사진 URL 및 역할(MARKETER)을 저장합니다. UserSessionModel(user_sessions)은 브라우저 세션 쿠키 토큰을 7일 슬라이딩 윈도우(expires_at)로 관리합니다. base.py는 PostgreSQL과 SQLite 모두에서 시간대 왜곡 없는 UTC 타임스탬프를 보장하는 utcnow()를 제공합니다.

app/schemas/deliverables.py Subagent Deliverable Contracts

서브에이전트 산출물을 정의하는 엄격한 Pydantic v2 계약 스키마:
• MarketSensingDeliverable ([P1]): 거시 트렌드, 경쟁사 강점/취약점, 감성 분석, 전략적 기회.
• CampaignBriefDeliverable ([P2]): 핵심 가치 제안, 3종 타겟 페르소나, 3종 메시징 필러, 톤앤보이스.
• CreativeContentDeliverable ([P3]): 헤드라인/본문/CTA 카피, 16:9 비주얼 프롬프트, GCS URI.
• PerformanceInsightsDeliverable ([P4]): 채널별 배분, 기대 ROAS, 전환수, CTR. validate_budget_conservation 검증자가 총비율 합산 100.0%를 수학적으로 보정합니다.

app/schemas/campaign.py, auth.py, errors.py REST API Contracts

• CampaignStage (5단계 DAG Enum): MARKET_SENSING → STRATEGY_BRIEF → CREATIVE_CONTENT → PERFORMANCE_INSIGHTS → MEDIA_EXECUTION → COMPLETED.
• StageApprovalRequest: 승인/수정 액션(action="approve" | "revise"), 피드백, 인라인 수정 데이터(deliverableUpdates).
• auth.py: OIDC ID Token 검증 요청(GoogleAuthRequest) 및 프로필 응답.
• errors.py: RFC 7807 Problem Details 표준 준수 ErrorResponse.

2.3. 오케스트레이터 코어 계층 (`app/orchestrator/`)

app/orchestrator/engine.py CampaignOrchestrationEngine

5단계 순차 DAG의 상태 전이를 총괄합니다. create_campaign()은 세션 초기화 즉시 Stage 1(Market Sensing)을 실행하고 마케터 검토를 위해 PAUSED_FOR_REVIEW로 일시정지합니다. approve_stage()는 수정된 산출물을 병합하고 다음 스테이지를 호출하며, Stage 3 승인 시점에 인메모리 드래프트 이미지를 GCS에 영구 커밋합니다. 수정 요청 시에는 드래프트 이미지를 파기하고 현재 단계를 재실행하며, rollback_stage()는 직전 단계($N o N-1$)로 원자적 상태 복원을 수행합니다.

app/orchestrator/agent_runner.py Dual-Path Execution Bridge

ADK Runner의 대화형 에이전트 턴과 결정론적 비즈니스 엔진 간의 교량 역할을 수행합니다. 오케스트레이터 모델은 FallbackGemini(app/models_fallback.py)로 래핑되어 gemini-3.1-pro-preview 장애 시 gemini-2.5-pro로 자동 장애 복구(Failover)됩니다. 1차로 ADK 에이전트 턴(Runner.run_async)을 호출하여 LLM의 Function Call 결과를 포착하고, 예외 발생 시 CampaignOrchestrationEngine의 결정론적 메서드로 즉각 자동 폴백합니다.

app/orchestrator/a2a_client.py Triple-Tier A2A Client

서브에이전트 실행을 관장하는 다계층 디스패처:
• **Tier 1 (Remote Agent Runtime RPC)**: A2A_P{N}_URL 엔드포인트로 JSON-RPC 2.0 message/send 패킷을 전송. Google OAuth 토큰 및 X-User-Id 헤더 자동 첨부.
• **Tier 2 (Direct Agent Platform SDK with Multi-Tier Fallback)**: 원격 호출 실패 시 GenAI SDK 및 중앙 재시도 정책(HttpRetryOptions)을 적용하며, 1차 모델(gemini-3.5-flash-lite) 실패 시 2차 폴백 모델(gemini-2.5-flash)로 투명 전환.
• **Tier 3 (Deterministic Heuristic Fallback)**: 네트워크 단절 시 도메인 규칙 및 지능형 정규식 파서 기반 데이터로 안전하게 폴백.

app/orchestrator/draft_store.py & security.py Memory Cache & Guardrails

• DraftImageStore: threading.Lock()으로 보호되는 인메모리 비주얼 드래프트 버퍼. Stage 3 미승인 이미지를 메모리에 보관하여 승인 전 GCS 오염을 차단하고, 수정 요청 시 즉시 삭제합니다.
• SecurityManager: Google Cloud Model Armor API(location="us")를 비동기 호출하여 프롬프트 인젝션, 탈옥, 악성 링크, 개인정보(SDP)를 검사하며, 위반 탐지 시 즉시 차단하는 **Fail-Closed** 보안을 강제합니다. 또한 구글 OIDC 서명 검증을 수행합니다.

3 Orchestrator와 Agent Runtime 서브에이전트 구동 및 협업 메커니즘

Protocol & Lifecycle

Direct A2A (HTTP JSON-RPC 2.0) 프로토콜 규격

서울 리전(asia-northeast3)에서 Agent Gateway의 501 Unimplemented 제약사항에 따라, Cloud Run Orchestrator와 Agent Runtime은 **Direct A2A** 방식으로 통신합니다. 요청 시 Cloud Run App 서비스 계정(version1-app)의 Google OAuth 2.0 Bearer 토큰을 첨부하고, 서브에이전트 측은 자체 서비스 계정(version1-subagent)의 **SPIFFE Workload Identity**로 호출자의 신원을 상호 검증합니다.

# Direct A2A Request Specification
POST ${A2A_P{N}_URL}/message/send
Authorization: Bearer <Google_Access_Token>
X-User-Id: <UUID-Marketer-Id>
Content-Type: application/json
{ "jsonrpc": "2.0", "method": "message/send", "params": { "sessionId": "...", "userId": "...", "stage": "...", "inputData": { ... } }, "id": "..." }

5단계 순차 DAG 및 원자적 롤백 메커니즘

캠페인은 단계별로 완전한 인간 검토(HITL) 게이트를 통과해야만 전진할 수 있습니다. 각 단계가 생성되면 상태는 즉시 PAUSED_FOR_REVIEW가 되며, 마케터는 화면에서 산출물 필드를 자유롭게 수정한 후 승인(approve)하거나, 피드백을 입력하여 해당 단계를 재실행(revise)할 수 있습니다.

단일 스텝 롤백 규칙 (N → N-1 Rollback) POST /campaigns/{id}/rollback
현재 단계가 $N$일 때 정확히 $N-1$ 단계로 상태를 역전이시킵니다. 이전 단계의 확정된 데이터는 보존되며, 현재 단계의 데이터만 안전하게 초기화되어 마케터가 전략이나 프롬프트를 즉시 재작업할 수 있습니다.
