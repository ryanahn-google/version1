C4 Level 1 Context

핵심 목표 & 비즈니스 가치

Nova Electronics Corp의 신제품 출시 시 마케터는 브랜드 가이드라인과 예산 제약 조건 하에 시장 센싱, 크리에이티브 브리프, 키 비주얼 생성, 채널별 미디어 믹스 및 ROAS 예측을 수작업으로 취합했습니다. MVC는 오케스트레이터가 주도하는 4개의 도메인 특화 에이전트를 통해 이를 자동화하며, 각 단계마다 검토 및 수정(HITL Gate)을 거쳐 인간 마케터의 최종 승인을 받은 후 다음 단계로 전진합니다.

🎯 엔터프라이즈 보안 가이드레일 Model Armor (us) 템플릿으로 프롬프트 인젝션/탈옥, 악성 URI, RAI, SDP(PII)를 사전에 차단
📊 결정론적 예산 보존 (100%) P4 에이전트 채널 할당 비율 합계가 100.0%에 수렴하도록 Pydantic 검증

3 ADK 루트 오케스트레이터 & A2A 클라이언트 (C4 Level 3)

Google ADK Runner, 도구 체이닝, Dual-Mode A2A 실행 및 다계층 폴백 구조

C4 Level 3 Component

Root Orchestrator Agent (ADK)

gemini-3.1-pro (global)

FastAPI 라이프사이클 컨텍스트 내에서 ADK Runner가 마케터의 대화형 턴을 처리합니다. 마케터의 자연어 요청을 해석하여 세부 캠페인 세션을 구성하고, 단계별 승인 및 롤백 도구를 직접 호출합니다. *Agent Platform SDK 바인딩은 gemini-3.1-pro-preview 식별자를 사용하며 시스템 표준 명칭은 gemini-3.1-pro로 통일.

바인딩된 5대 오케스트레이터 도구 (Tools):
  • parse_campaign_prompt : 자연어 브리프 구조화
  • create_campaign_session : 세션 생성 및 P1 트리거
  • get_campaign_status : 현재 진행률 및 산출물 조회
  • approve_campaign_stage : 승인(Approve) 및 수정(Revise)
  • rollback_campaign_stage : 직전 단계(N-1) 안전 롤백

Dual-Mode A2A Client

A2A-Version: 0.3

A2ASubAgentClient는 환경 변수(A2A_P1_URL 등) 존재 여부에 따라 원격 Agent Runtime 호출과 로컬 인프로세스 실행을 투명하게 전환합니다.

Mode A: Remote JSON-RPC over A2A
Agent Platform Agent Runtime 엔드포인트로 JSON-RPC 2.0 message/send 패킷 전송 및 SPIFFE 검증
Mode B: In-Process Fallback with Structured Outputs
오프라인 테스트나 로컬 개발 시 Agent Platform GenAI SDK로 Pydantic 스키마를 강제하여 즉시 산출물 생성

5 Human-in-the-Loop (HITL) 캠페인 상태 머신

마케터 검토 게이트(PAUSED_FOR_REVIEW), Approve / Revise / Rollback 3대 전이 규칙

HITL State Machine
1. Approve (다음 단계 전진)

마케터가 산출물을 승인하면 N ➔ N+1 단계로 전진합니다. Stage 4 승인 시 Stage 5(MEDIA_EXECUTION) 미디어 믹스 실행 계획으로 전진하며, Stage 5 승인 시 최종 COMPLETED 상태로 종결됩니다. Stage 3 승인 시점: DraftImageStore의 인메모리 드래프트 이미지를 GCS 버킷에 영구 커밋합니다.

2. Revise (피드백 반영 재실행)

마케터의 텍스트 피드백(예: "더 고급스러운 톤앤매너로 수정")을 주입하여 현재 단계를 재실행합니다. 세션의 revision_count가 증가합니다. Stage 3 수정 시점: DraftImageStore.delete_draft()를 호출하여 기존 인메모리 바이너리를 즉시 파기하고 새로운 비주얼 생성을 보장합니다.

3. Rollback (직전 단계 안전 복귀)

전용 엔드포인트(POST /api/v1/campaigns/{sessionId}/rollback)를 통해 즉시 직전 단계(N ➔ N-1)로 되돌아가 이전 기획 방향이나 전략을 다시 수정할 수 있습니다 (Stage 5 ➔ Stage 4 포함).

DRS 준수 V4 서명 URL 307 임시 리다이렉트

조직 정책상 GCS 버킷 공개 접근이 차단된 상태에서, Cloud Run은 인증된 사용자에게만 1시간 유효한 Google Cloud Storage V4 Signed URL을 동적으로 발급하여 HTTP 307 Temporary Redirect로 브라우저에 전달합니다. 객체는 사용자 격리 경로(users/{user_id}/campaigns/{session_id}/{filename})로 안전하게 저장됩니다.

💡 핵심 아키텍처 이점 & 헬퍼 엔드포인트:
• 0 Bytes Cloud Run Memory Buffering: 대용량 이미지를 메모리에 로드하지 않음
• 0 Bytes Cloud Run Egress Cost: 브라우저가 GCS로부터 직접 다운로드
• 완벽한 보안: OIDC 인증 없는 비인가자의 직접 다운로드 원천 차단
• 드래프트 및 토큰 API: /draft-image(인메모리 프리뷰) 및 /visual-token(직접 서명 토큰 JSON) 완벽 지원

7 보안 & 제로 트러스트(Zero-Trust) 네트워크 경계

Google OAuth 2.0 OIDC, Model Armor SDP 가드레일, Direct VPC Egress, 최소 권한 IAM

Security Architecture
1

OAuth 2.0 OIDC

모든 보호된 REST 엔드포인트에 Google OAuth 2.0 ID 토큰 및 안전한 HTTP-only 세션 쿠키 검증 강제.

2

Model Armor 활성 가드레일

us 멀티리전 템플릿(version1-guardrails)으로 프롬프트 인젝션/탈옥(LOW+), 악성 URI, 4대 RAI(MEDIUM+), SDP(PII)를 검사하며 위반 시 즉각 Fail-Closed 차단.

3

Direct VPC Egress & Zero-Trust Firewall

Serverless VPC 커넥터 오버헤드 없이 전용 서브넷(10.10.0.0/24)과 Cloud NAT 사용. Ingress/Egress Default Deny 및 최소 포트만 허용하는 제로 트러스트 방화벽 정책 강제.

4

Cloud SQL Auth Proxy

공인 IP 노출 완전 차단(0.0.0.0/0 없음). Unix 도메인 소켓 마운트와 IAM 기반 mTLS 암호화 채널 강제 (TCP 3307 방화벽 터널링).

Custom VPC (version1-vpc) Zero-Trust 방화벽 규칙 명세 (Staging & Prod)

Terraform Provisioned & Verified

Cloud Run Direct VPC Egress는 단방향 아웃바운드 전용이며, 사용자 인바운드 트래픽은 Google Front End(GFE)를 통해 인입되므로 인바운드를 100% 차단(Zero Attack Surface)하고, 아웃바운드는 필수 엔드포인트 포트만 선별 허용합니다.

규칙 리소스 방향 우선순위 프로토콜 / 포트 대상 대역 동작 및 보안 목적
version1-ingress-deny-all INGRESS 65000 ALL 0.0.0.0/0 DENY: 외부 직접 인입 원천 차단 (Zero Inbound Attack Surface)
version1-egress-deny-all EGRESS 65000 ALL 0.0.0.0/0 DENY: 미승인 아웃바운드 트래픽 기본 차단 및 데이터 유출 방지
version1-egress-allow-https EGRESS 1000 tcp: 443 0.0.0.0/0 ALLOW: Google APIs (Agent Platform, Cloud Storage, Model Armor) & Web Grounding
version1-egress-allow-cloudsql-proxy EGRESS 1010 tcp: 3307 0.0.0.0/0 ALLOW: Cloud SQL Auth Proxy mTLS 클라이언트-서버 터널 암호화 통신
version1-egress-allow-dns EGRESS 1020 tcp: 53, udp: 53 0.0.0.0/0 ALLOW: Cloud NAT 내부 DNS 도메인 네임 해석
최소 권한 IAM & Direct A2A 보안 아키텍처

• Cloud Run Orchestrator SA (version1-app): BigQuery 직접 편집 권한을 제거하고 Cloud Logging Sink 전용 Writer Identity를 통해서만 version1_telemetry 데이터셋에 적재합니다.
• Subagent SA (version1-subagent): 버킷 관리 권한을 배제하고 roles/storage.objectAdmin으로 최소화하여 Agent Runtime 서브에이전트가 격리된 경로에만 아티팩트를 쓰도록 강제합니다.
• Direct A2A Ingress: Agent Gateway의 서울 리전 501 Unimplemented에 따라, Cloud Run과 Agent Platform Agent Runtime 간에는 SPIFFE 기반 Agent Identity(--agent-identity)와 Direct VPC Egress를 통한 안전한 내부 통신을 수행합니다 (ADR-0008).

Active Resilience
1. Centralized HTTP Retry Jittered Backoff

app/retry_policy.py: HttpRetryOptions로 지수 백오프 및 무작위 지터 일괄 적용.
• 설정: 3회 시도, 초기 1.0s, 최대 10.0s, 승수 2.0, 지터 1.0.
• 대상: 408, 429, 500, 502, 503, 504. Orchestrator 및 전 서브에이전트 보호.

2. Multi-Tier Model Fallback FallbackGemini

app/models_fallback.py: ADK BaseLlm 기반 복합 모델로 무중단 장애 복구 보장.
• Orchestrator: gemini-3.1-pro-preview → gemini-2.5-pro.
• Subagents: gemini-3.5-flash-lite → gemini-2.5-flash.

3. Async Visual Synthesis 2-Attempt Loop

app/agents/creative_content/agent.py: Nano Banana 2 Lite 이미지 생성 완전 비동기화.
• 비동기 실행: client.aio.models.generate_content로 메인 루프 블로킹 방지.
• 2회 재시도: 25s 타임아웃, 지수 백오프 및 asyncio.to_thread GCS 저장.

4. Database Fault Resilience @db_retry

app/orchestrator/session_repo.py: 전 세션 쿼리 메서드 대상 데코레이터.
• 동작: OperationalError, DBAPIError 포착 시 3회 지수 백오프.
• 효과: Cloud SQL Auth Proxy 소켓 재연결 및 트랜잭션 락 일시 장애를 100% 흡수.

11 아키텍처 결정 기록 (ADR Index)

FDE 표준 아키텍처 결정 기록 9종 및 선택 근거 요약

ADR-0001 ~ ADR-0009
ADR-0001

A2A Multi-Agent DAG Orchestration

단일 거대 프롬프트 대신 4개 독립 Reasoning Engine과 중앙 오케스트레이터 분리 채택.

ADR-0002

Hybrid Model & Global Pinning

Pro + Flash Lite + Nano Banana 2 하이브리드 조합, global 엔드포인트 고정 및 FallbackGemini 다계층 모델 장애 복구.

ADR-0003

Dual-Mode A2A Client & Hybrid DB

원격 Agent Runtime과 로컬 인프로세스 실행을 투명 지원하며 @db_retry 기반 Cloud SQL 장애 복구 및 A2A 재시도 보장.

ADR-0004

Multi-Project CI/CD & Native Approval

CI/CD 허브, 스테이징, 프로덕션 3개 프로젝트 격리 및 Cloud Build 수동 승인 게이트 연동.

ADR-0005

Direct VPC Egress & Auth Proxy

VPC 커넥터 오버헤드 제거, Cloud Run Direct VPC Egress와 Cloud SQL Auth Proxy 유닉스 소켓 바인딩.

ADR-0006

Hybrid Generated Visual Storage

미승인 시 인메모리 드래프트 보관, 승인 시 GCS 버킷에 영구 커밋하는 2단계 생명주기 분리.

ADR-0007

DRS Signed URL Streaming Proxy

Cloud Run 메모리 버퍼링 및 아웃바운드 Egress 0-Byte 달성을 위한 V4 Signed URL 307 임시 리다이렉트.

ADR-0008 Superseded

Direct A2A & Orchestrator Model Armor

Agent Gateway 서울 501 오류에 따라 Direct A2A(SPIFFE)와 오케스트레이터 직접 Model Armor(us 멀티리전 활성 가드레일) 채택.

ADR-0009

Agent Platform Two-Stage Quality Gate

PR 단위/통합 테스트 게이트(119개 100% 통과) + 스테이징 배포 후 골든 데이터셋 9종 평가 회귀 차단 파이프라인.
